StateMachineRunner

final class StateMachineRunner (View source)

internal  This class is not covered by the backward compatibility promise for PHPUnit
 

Runs a state machine with the choices of an example of a property, so that its steps are generated, replayed, and shrunk together with the arguments of the property.

The initializations are taken first, in the order in which they are declared, those of a parent class before those of the class that extends it. Then each step is drawn like an element of a list: a choice whether another step is taken (0 = stop), the index of its rule in the same order of the rules, and the arguments of the rule, all in one span.

A value from a pool is drawn as its position among the values of the pool that were not consumed, counted from the value that was produced last, in a span of the kind Reference, or ConsumingReference when the value is consumed. A step that produces a value for a pool ends with a choice that is always 0, in a span of the kind Referable. Both spans are labelled with the pool, and both are drawn by Pool of sebastian/choice-sequence. They tell the shrinker which value a position refers to: when it deletes a step that produced a value for the pool, or that consumed one, it changes the positions that the steps after it draw, so that they take the values that they took before.

While choices are drawn at random, only rules whose preconditions hold and whose pools have values are drawn, and each example enables a random subset of the rules (swarm testing), without drawing choices for this. When a choice sequence is replayed, a rule that cannot be applied is skipped and does not count as a step. The choices for its arguments are drawn nevertheless, so that the choices after them are read as the steps that they were drawn for: when the step that produced the only value of a pool is deleted, the steps that took the value are skipped, and the steps after them are taken as before. No more steps are taken when no rule can be applied.

The invariants are checked after the initializations and after every step, except for those with #[StateMachineInvariant(atEnd: true)], which are checked after the initializations and after the last step.

With an exporter, the steps are recorded as PHP code that calls the methods of the state machine, for the report of the minimal counterexample: a value that a step produced is assigned to a variable that is named after its pool, the value that another step returned is written as a comment unless it is null, with ?> written as ?> as it would end the comment, and an invariant is written only when it failed.

The state machine is referred to as $machine in this code. The report assigns the arguments of the property to variables that are named after its parameters before the steps, so when one of them is named machine, the state machine is referred to as $stateMachine, which is followed by a number when this name is the one of a parameter as well, and a value of a pool is not assigned to a variable with the name of a parameter either.

private LARGEST_PLANNED_NUMBER_OF_STEPS

The largest number of steps that is planned for an example whose steps are drawn at random: a step draws at least two choices, whether it is taken and its rule, so no more steps can be taken before the maximum number of choices of an example has been drawn.

array
stepsExportedWith(CounterexampleExporter $exporter)

The steps that were taken, as steps() returns them, followed by the step that is being taken or the invariant that is being checked, for the report of the example that was run when the PHP process ended. The steps that were taken without an exporter are written as PHP code with the given one: their arguments are exported in the state in which the steps left them, and the values that they returned are not written.
