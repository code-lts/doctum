Falsification

final class Falsification (View source)

internal  This class is not covered by the backward compatibility promise for PHPUnit
 

How an example falsified a property.

Two examples falsify a property in the same way when the throwables that ended them have the same class and were raised at the same location, or when both exceeded the time limit. The location is the one PHPUnit reports for a throwable: the first frame of its stack trace that is not in PHPUnit's own code, or else the file and line of the throwable itself. The file and line of the throwable alone would not do, because every failed assertion is raised in PHPUnit's own code.

When unbounded recursion reaches the limit of PHP's call stack, or the limit of the nesting level of function calls of Xdebug, the error is raised by whichever call of the recursion exceeds the limit, which depends on how deep the call stack was when the recursion started, and on how much of it the calls use, which differs between versions of PHP. So that the same recursion has the same location, the location of this error is the frame of the recursion that comes first, by file and then by line, among the frames of the cycle that repeats at the top of its stack trace. The frames further down, of a finite recursion that led to the unbounded one, for instance, whose depth can depend on the example, are not considered. When no cycle repeats at the top of the stack trace, the frames that occur more than once in it are considered instead.

The path of a file below the directory of the configuration file, or below the working directory when there is no configuration file, is relative to it, so that the location depends neither on where a project is checked out nor on the working directory of the process.

The name of an anonymous class contains the path of the file in which it is declared and a counter that depends on the order in which anonymous classes are compiled, and the name of the class of a test double ends in random characters. So that the same failure has the same signature in every process, the signature names the class that the class of such a throwable extends, the first one that is neither anonymous nor a test double. Like the location, the class of the throwable itself is kept as it is.

Whether two examples falsify the property in the same way is told by the failure signature of sebastian/choice-sequence, so that failures are compared in the same way wherever that library is used.
