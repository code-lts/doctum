PropertyRunner

final class PropertyRunner (View source)

Runs the examples of the properties of a test suite one at a time, for tools that drive property-based tests themselves, a fuzzer that is guided by code coverage, for instance.

Everything that is passed to this API and returned by it is data: strings, integers, null, and arrays of these. No object of a class of one of PHPUnit's dependencies crosses it, so it is used in the same way whether PHPUnit is installed with Composer or used from its PHAR, in which the names of these classes are prefixed.

PHPUnit is booted once per process, and it cannot be booted in a process in which it is already running, by a test that the test runner runs, for instance. A boot that fails because the configuration file cannot be found or read changes nothing and can be retried. A boot that fails for another reason cannot be retried, see boot(). The configuration file and its bootstrap script are loaded as for a test run, but nothing is printed, no code coverage is collected, nothing is logged, and no extensions are loaded. As nothing is printed, an error that PHPUnit triggers while it is booted, about a property that cannot be checked, for instance, is raised as an exception, as the test run fails because of it. A warning that PHPUnit triggers while it is booted, about a configuration file that did not pass validation, for instance, is raised as an exception when the test run fails because of it, which it does unless the configuration file sets failOnPhpunitWarning to false, and is discarded otherwise. This is so for every test in the test suite that the configuration file configures, also for one that the filter leaves out, as the test suite is built before it is filtered.

As in a test run, the random number generators whose state is global to the process, the one that mt_rand() uses, for instance, are seeded before each example when a random seed is passed while PHPUnit is booted, or when the configuration file configures a random execution order, for which PHPUnit chooses a random seed itself. The seed for an example is derived from the random seed and the property, so that the example gets the same random numbers in every process that is booted with the same random seed. randomSeed() tells which random seed is used.

An example is run with its full lifecycle, from the hook methods that are called before the property to the ones that are called after it, and with the time limit that is passed, which covers generating its arguments as well as running it. Its arguments are generated from choices as when PHPUnit checks the property, and it draws values with draw() from the same choices. It is neither shrunk nor reported. The issues that it triggers are handled as in a test run, but they are not reported either.

While code of the project is run, when PHPUnit is booted, while an example runs, and while the hook methods of a test class that are called before its first test and after its last test are called, the error handlers of the caller are hidden: they are not called, and PHPUnit's error handler does not forward an issue to them. The error handlers that the bootstrap script of the project and these hook methods register are the ones of the project: as in a test run, they are registered while code of the project is run, and only then. Afterwards, the error handlers of the caller are registered as before, for the error levels that they were registered for, also when code of the project did not remove an error handler that it registered, in a generator, for instance. Only code of the project that removes at least two error handlers more than it registered removes error handlers of the caller: the one that was active is then registered again, for all error levels.

The output that an example prints is not printed, as in a test run. Output buffering that code of the project started without ending it, in a generator, for instance, is ended afterwards, and what was buffered is discarded, so that the level of output buffering of the caller is the one from before.

The time limit of an example is enforced with the SIGALRM signal. While an example runs, the handler of this signal, a pending alarm, and whether signals are handled asynchronously are PHPUnit's. Afterwards, the ones of the caller are restored, and an alarm of the caller is set again for the rest of its time: an alarm that would have gone off while the example ran goes off one second after it. As in a test run, an example that catches the exception with which it is aborted when it exceeds its time limit, as code that catches every throwable does, keeps running.

When an example ends the process, with exit() or with a fatal error, for instance, its output is discarded, the handler of the SIGALRM signal, the alarm, and whether signals are handled asynchronously of the caller are restored, and the error handlers of the caller are registered as before, in a shutdown function that is registered when PHPUnit is booted, before the hook methods of the prepared test class that are called after its last test are called. PHPUnit prints nothing, unless one of these hook methods raises an exception, which is written to the standard error stream, see below, and the process ends with the exit status of the example. The shutdown functions that the caller registers after booting PHPUnit are called after it, and the ones that it registers before are called before it.

As in a test run, one test class is prepared at a time. The hook methods of a test class that are called before its first test are called before the first example of one of its properties is run, and the ones that are called after its last test are called before an example of a property of another test class is run, when finish() is called, or when the process ends. When one of the former raises an exception, every example of a property of the test class is aborted with that exception, and when one of them skips the tests of the test class, every example is skipped. The latter are only called in the process that prepared the test class: a process that is forked from it, while an example runs or between examples, does not call them for this test class, but does for a test class that it prepares itself.

When one of the hook methods that are called after the last test of a test class raises an exception, or marks the test as incomplete or skipped, no example is left to which this could be attributed: an AfterLastTestMethodFailedException is raised instead, by finish(), or by replay() or generate() for a property of another test class, before the test class of this property is prepared and the example is run. The test class that was prepared is finished then, and its hook methods are not called again, so that the call can be repeated, which prepares the other test class and runs the example. When the process ends, nothing can be raised: the message of the exception, followed by a line break, is written to the standard error stream instead, and the exit status of the process is not changed. Nothing is written for a test class that was finished before, with finish(), for instance.

The result of an example tells how it ended, how it falsified the property, and which choices it consumed, with their spans and the maxima of the choices. The kind of a span, when it has one, is the name of the case of SpanKind of sebastian/choice-sequence in lowercase: 'bytes', 'characters', 'element', 'requiredelement', 'referable', 'reference', or 'consumingreference'. On request, the result also has the arguments of the example, the values that it drew with draw(), and the steps of its state machine, exported as PHPUnit reports them for a counterexample. They are null otherwise, and when no arguments were generated for the example.

The signature of how an example falsified the property is the same for the same failure in every process, whatever its working directory, so that failures that are found in different processes can be compared by it. The path of a file below the directory of the configuration file is relative to it, and the signature does not name the class of an anonymous throwable or of a test double, whose names differ between processes, but the first class that it extends which is neither. The class of the throwable itself is kept as it is.

An example that triggers an issue for which the test run fails, a warning when the test runner is configured to fail on warnings, for instance, falsifies the property like an example that fails. Its failure has no class, and its signature names the kind of the issue and where it was triggered.

An example that fails or errors without checking the property is aborted rather than falsifying it: when a generator raises an exception while its arguments are generated, when it ends before its test method is called, in setUp(), for instance, or when its state machine cannot be run. When PHPUnit checks the property, such an example is the error of the property, which is reported without being shrunk. An example whose arguments take longer to generate than its time limit allows is aborted, too. The failure of an aborted example tells how it ended.

static PropertyRunner boot(string|null $configurationFile = null, string|null $filter = null, int|null $randomSeed = null)

Loads the configuration file and its bootstrap script and builds the test suite, with only the tests that match the filter, as with the --filter option of the test runner.

Booting PHPUnit can only be retried when it failed because the configuration file cannot be found or read. When it failed for another reason, because the bootstrap script or the test suite cannot be loaded, or because PHPUnit triggered an error or a warning, for instance, the global state of PHPUnit and of PHP has been changed in ways that cannot be reset: the constants and settings of the configuration file are defined, the bootstrap script and the test classes are loaded, and PHPUnit is configured for this configuration file. Every further call then raises an AlreadyBootedException, also one with another configuration file or another filter, so that examples can only be run in another process.

Parameters

string|null $configurationFile

the configuration file, null to look for one in the working directory as the test runner does
string|null $filter

the filter, null for all tests
int|null $randomSeed

the random seed with which the random number generators are seeded before each example, as with the --random-seed option of the test runner, null to seed them only when the configuration file configures a random execution order

array replay(string $id, array $choices, int $timeLimit, bool $exportValues = false)

Runs an example of the property with arguments that are generated from the given choices.

The given choices need not be the ones that an example consumes: a choice that is greater than the maximum of the choice that is consumed in its place is replaced with this maximum, a choice that is consumed after the last of the given choices is 0, and the given choices that are left when the example has consumed its choices are ignored. The choices of the result are the ones that the example consumed.

void finish()

Calls the hook methods of the test class that was prepared last that are called after its last test, as they are called before an example of a property of another test class is run, rather than only when the process ends. When an example of one of its properties is run afterwards, the test class is prepared again.

Nothing is done when no test class is prepared: before the first example, and when the test class that was prepared last is already finished. As before an example of a property of another test class is run, the hook methods are not called when the ones that are called before the first test of the test class did not succeed, and not in a process that is forked from the one that prepared the test class.
